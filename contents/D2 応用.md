「D2」の基本（ノード・接続・形状）を超えて、**入れ子・クラス・ER 図・シーケンス図・グリッド**を組み合わせた凝った図の例です。
コンテナを何階層にも重ねて、階層をまたぐ接続を引いても、レイアウトは自動で整います。
PlantUML や Mermaid では配置の調整に苦労しがちな「システム全体の構成図」を、短いテキストで描けるのが D2 の強みです。

基本構文は「D2」のメモを参照してください。

---

## 1. マイクロサービスの全体構成図

コンテナを 3 階層に入れ子にし、`classes` で見た目を使い回し、階層をまたいで接続します。

```d2
direction: right

classes: {
  svc: {
    style: {
      fill: "#e3f2fd"
      stroke: "#1976d2"
      border-radius: 8
    }
  }
  store: {
    shape: cylinder
    style: {
      fill: "#fff3e0"
      stroke: "#f57c00"
    }
  }
  queue: {
    shape: queue
    style: {
      fill: "#f3e5f5"
      stroke: "#8e24aa"
    }
  }
}

利用者: {shape: person}
CDN: {shape: cloud}

クラウド: {
  ゲートウェイ: {
    LB: ロードバランサ
    認証: 認証プロキシ
    LB -> 認証
  }

  アプリ層: {
    注文: 注文サービス {class: svc}
    在庫: 在庫サービス {class: svc}
    決済: 決済サービス {class: svc}
    通知: 通知サービス {class: svc}
  }

  データ層: {
    注文DB: 注文 DB {class: store}
    在庫DB: 在庫 DB {class: store}
    キャッシュ: キャッシュ {class: store}
    イベント: イベントバス {class: queue}
  }
}

外部決済: 外部決済サービス {shape: cloud}

利用者 -> CDN: 静的ファイル
利用者 -> クラウド.ゲートウェイ.LB: HTTPS
クラウド.ゲートウェイ.認証 -> クラウド.アプリ層.注文: 検証済み

クラウド.アプリ層.注文 -> クラウド.データ層.注文DB
クラウド.アプリ層.注文 -> クラウド.アプリ層.在庫: 在庫確認
クラウド.アプリ層.在庫 -> クラウド.データ層.在庫DB
クラウド.アプリ層.在庫 -> クラウド.データ層.キャッシュ
クラウド.アプリ層.注文 -> クラウド.アプリ層.決済: 支払い
クラウド.アプリ層.決済 -> 外部決済: API 呼び出し

クラウド.アプリ層.決済 -> クラウド.データ層.イベント: 決済完了
クラウド.データ層.イベント -> クラウド.アプリ層.通知: 購読
```

## 2. シーケンス図

`shape: sequence_diagram` を指定すると、同じ D2 の書き方でシーケンス図になります。
`グループ名: { ... }` で処理のまとまりを囲み、`ノート` で補足も書けます。

```d2
shape: sequence_diagram

利用者: {shape: person}
画面
API
認証
DB: {shape: cylinder}

利用者 -> 画面: ログイン操作
画面 -> API: POST /login
API -> 認証: 資格情報の検証
認証 -> DB: ユーザー検索
DB -> 認証: ユーザー情報
認証."トークンを発行"
認証 -> API: アクセストークン
API -> 画面: 200 OK
画面 -> 利用者: ホーム画面を表示

失敗時: {
  認証 -> API: 認証エラー
  API -> 画面: 401 Unauthorized
  画面 -> 利用者: エラーメッセージ
}
```

## 3. ER 図（テーブル間の関係）

`shape: sql_table` を複数並べて外部キーで結ぶと、ER 図になります。

```d2
direction: right

顧客: {
  shape: sql_table
  id: int {constraint: primary_key}
  name: varchar(64)
  email: varchar(255) {constraint: unique}
}

注文: {
  shape: sql_table
  id: int {constraint: primary_key}
  customer_id: int {constraint: foreign_key}
  ordered_at: timestamp
  total: decimal
}

注文明細: {
  shape: sql_table
  order_id: int {constraint: [primary_key; foreign_key]}
  product_id: int {constraint: [primary_key; foreign_key]}
  quantity: int
}

商品: {
  shape: sql_table
  id: int {constraint: primary_key}
  name: varchar(128)
  price: decimal
}

注文.customer_id -> 顧客.id
注文明細.order_id -> 注文.id
注文明細.product_id -> 商品.id
```

## 4. クラス図

`shape: class` では、フィールドとメソッドを書くだけでクラス図になります。
継承などの関係は、矢じりの種類を指定して表します。

```d2
direction: up

Figure: {
  shape: class
  +name: string
  -id: int
  +area(): float
  +draw(): void
}

Circle: {
  shape: class
  +radius: float
  +area(): float
}

Rectangle: {
  shape: class
  +width: float
  +height: float
  +area(): float
}

Circle -> Figure: {
  target-arrowhead.shape: triangle
  style.stroke-dash: 3
}
Rectangle -> Figure: {
  target-arrowhead.shape: triangle
  style.stroke-dash: 3
}
```

## 5. グリッドでダッシュボード風に並べる

`grid-rows` / `grid-columns` を指定すると、接続を引かずに升目へ整列できます。
構成の一覧表や、画面のレイアウト案を作るのに便利です。

```d2
grid-rows: 2
grid-gap: 12

稼働状況: {
  grid-columns: 3
  Web: 正常 {style.fill: "#c8e6c9"}
  API: 正常 {style.fill: "#c8e6c9"}
  DB: 遅延 {style.fill: "#fff9c4"}
}

リソース: {
  grid-columns: 2
  CPU: 45% {style.fill: "#c8e6c9"}
  メモリ: 82% {style.fill: "#ffe0b2"}
  ディスク: 91% {style.fill: "#ffcdd2"}
  ネットワーク: 12% {style.fill: "#c8e6c9"}
}
```

## 6. 使い分けの目安

* **D2:** 階層の深い構成図、ER 図、クラス図など、要素が多く入れ子になる図。見た目の統一（`classes`）も簡単
* **Mermaid:** フローチャートやガントチャートなど、手早く書ける標準的な図
* **PlantUML:** UML の細かな記法が必要な図（アクティビティ図・ステート図など）
