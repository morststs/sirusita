## nsenter コマンド

Linux の名前空間（namespace）に入って任意のプログラムを実行するコマンド。コンテナのプロセスに `docker exec` を使わず直接アクセスしたい場合や、コンテナが最小構成でシェルすら入っていない場合のデバッグに使う。

---

## 1. 基本の使い方

* **`nsenter -t <PID> -a <コマンド>`**：指定PIDが属する全名前空間（`-a`）に入ってコマンドを実行
* **`nsenter -t <PID> -n <コマンド>`**：ネットワーク名前空間（`-n`）のみに入って実行
* **`nsenter -t <PID> -m <コマンド>`**：マウント名前空間（`-m`）のみに入って実行
* **`nsenter -t <PID> -p <コマンド>`**：PID名前空間（`-p`）のみに入って実行
* **`nsenter -t <PID> -u <コマンド>`**：UTS名前空間（`-u`、ホスト名）のみに入って実行
* 引数なしでコマンドを省略すると、デフォルトで `$SHELL`（対話シェル）が起動する

```bash
# PID 12345 の全名前空間に入ってシェルを起動
sudo nsenter -t 12345 -a
```

---

## 2. コンテナのデバッグ

コンテナには `bash` や `curl` などのデバッグツールが入っていないことが多い（distroless イメージ等）。その場合、ホスト側から対象コンテナの名前空間に入ればホストのツールがそのまま使える。

* **`docker inspect -f '{{.State.Pid}}' <コンテナ名>`**：コンテナのメインプロセスのホスト側PIDを取得
* **`nsenter -t <PID> -n ss -tlnp`**：コンテナのネットワーク名前空間だけに入り、ホストの `ss` でリスニングポートを確認
* **`nsenter -t <PID> -a -- bash`**：全名前空間に入りつつホストのbashを使ってファイルシステムを調査

```bash
# distrolessイメージなどbashが入っていないコンテナのネットワークを調査
PID=$(docker inspect -f '{{.State.Pid}}' myapp)
sudo nsenter -t "$PID" -n ss -tlnp

# 全名前空間に入って、ホスト側の充実したツールでコンテナ内部を調査
sudo nsenter -t "$PID" -a -- bash
```

---

## 3. 主要オプション一覧

* **`-t, --target <PID>`**：対象とするプロセスのPIDを指定
* **`-a, --all`**：対象プロセスが属する全ての名前空間に入る
* **`-m, --mount`**：マウント名前空間（ファイルシステムの見え方）
* **`-u, --uts`**：UTS名前空間（ホスト名・ドメイン名）
* **`-i, --ipc`**：IPC名前空間（プロセス間通信）
* **`-n, --net`**：ネットワーク名前空間（IPアドレス・ポート・ルーティング）
* **`-p, --pid`**：PID名前空間（プロセスID空間）
* **`-U, --user`**：ユーザー名前空間（UID/GIDのマッピング）
* **`-r, --root[=<パス>]`**：ルートディレクトリを対象プロセスに合わせて変更

```bash
# ネットワークとマウントの名前空間だけに入る
sudo nsenter -t 12345 -n -m -- bash
```

> 注意: 多くの操作は root 権限（`sudo`）またはそれに準じる capability（`CAP_SYS_ADMIN` / `CAP_SYS_PTRACE`）が必要。
